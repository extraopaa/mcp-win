# MCP Win v1 — Studio documentaire

La v1 conserve le MCP HTTP sécurisé et les outils v0.4, et passe à **42 outils**. Aucun service d’IA payant n’est ajouté : l’assistant connecté prépare le contenu, les moteurs locaux produisent les fichiers.

## De beaux documents par défaut

`create_document` crée des PDF, DOCX et PPTX avec une composition professionnelle sans devoir demander « une belle mise en page ». Titres hiérarchisés, couleurs, typographie, tableaux, encadrés, images et pagination sont pris en charge. Les documents longs PDF/Word peuvent recevoir une couverture et un sommaire. `raw:true` exige une demande explicite de contenu brut. `write_spreadsheet` applique une présentation lisible aux nouveaux classeurs : en-têtes, largeurs et formats numériques.

```json
{"path":"rapport.pdf","title":"Bilan trimestriel","blocks":[
  {"id":"intro","kind":"heading","level":1,"text":"Résultats"},
  {"id":"texte","kind":"paragraph","text":"Le trimestre en quelques chiffres."},
  {"id":"chiffres","kind":"table","columns":["Indicateur","Valeur"],"rows":[["Dossiers","125"],["Délai","2 jours"]]},
  {"id":"action","kind":"callout","text":"Priorité : réduire les délais de traitement."}
]}
```

`folder` peut être omis si un seul dossier est partagé ; sinon appeler `list_folders` et choisir un dossier writable. Les sorties ne remplacent pas silencieusement un fichier existant.

Les noms `style` sont professional/report/quote/invoice/commercial/course/presentation/minimal : ils choisissent le contexte éditorial dans le système visuel commun, sans inventer les rubriques métier. Pour une composition entièrement personnalisée, utiliser le moteur Typst existant ou un modèle Office.

## Identité visuelle

Dans **Studio documentaire → Identité visuelle**, enregistrer jusqu’à dix profils : organisation, contact, pied de page, couleurs, police et logo PNG/JPEG. Choisir le profil par défaut ou passer son identifiant dans `brand`. `list_brand_profiles` découvre les profils sans exposer les octets du logo. Arrêter le MCP pour modifier les profils.

Les modèles de documents générés conservent l’identité utilisée : une correction ciblée ne change pas de charte parce que le profil par défaut a changé. Les images sources sont vérifiées par empreinte.

## Contrôle qualité et aperçu

La création professionnelle contrôle les fichiers avant leur enregistrement. Pour PDF : ouverture, nombre de pages, rendu initial et objets texte hors page. Pour Office : structure OOXML et XML. `review_document` renvoie le rapport et les images des pages PDF demandées, à examiner par l’IA avant livraison.

Ce contrôle ne garantit pas l’absence de chevauchement ou une esthétique parfaite. Le rendu DOCX/PPTX/XLSX dépend du lecteur Office ; aucun rendu visuel Office universel n’est embarqué. Le sommaire Word est un champ actualisable par le lecteur.

## Recherche persistante et citations

`index_folder` construit un index SQLite FTS5 local par lots ; continuer avec `next_offset` lorsqu’il est présent. `search_index` renvoie les extraits pertinents et leur provenance : chemin, page/feuille et SHA-256. Les sources modifiées depuis l’indexation sont exclues jusqu’à actualisation. La recherche porte sur les mots, avec gestion des accents ; ce n’est pas une recherche par embeddings.

`create_document.citations` accepte les références `{folder,path,sha256,page,sheet,line}`. Le hash est revérifié avant génération ; ne pas inventer une localisation. Les extractions sont mises en cache sur disque, selon le contenu, pour limiter les lectures répétées.

## Corrections précises et validation locale

1. Appeler `inspect_document_elements` et conserver le SHA-256.
2. Passer les identifiants à `edit_document_elements` avec `expected_sha256`, `output_path` et les corrections.
3. La proposition reste privée, sans modification du fichier partagé.
4. Dans **Studio → Révisions**, comparer le diff et, pour PDF, les premières pages avant/après ; arrêter le MCP puis appliquer ou refuser.
5. Le bouton Annuler restaure la sauvegarde ou retire la nouvelle copie, sous contrôle de hash.

PDF produits par le générateur : blocs et cellules de tableau. Office importé : paragraphes et cellules DOCX/PPTX, cellules XLSX par `Feuille!A1`. Texte : lignes. Une modification `find`/`replacement` conserve les propriétés des segments OOXML ; un remplacement complet garde le style de départ de l’élément. Un PDF importé sans modèle de composition n’est pas rééditable comme un document Word.

## Workflows durables

`start_workflow` reçoit 1 à 50 étapes nommées ; les références `{"$ref":"etape.path"}` réutilisent leurs résultats. Les étapes autorisées sont create_document, write_text_file, write_spreadsheet, read_file, index_folder, search_index, ocr_file, extract_document_layout, review_document et create_archive. Aucun script arbitraire n’est exécuté.

`workflow_status` suit la progression ; `control_workflow` accepte pause/cancel/resume. Deux workflows simultanés maximum. L’arrêt du MCP suspend les travaux ; la reprise vérifie les dossiers et les empreintes, et ne rejoue pas les étapes terminées. Les intentions d’écriture sont journalisées avant modification pour récupérer une sortie après interruption.

Le Studio permet aussi une annulation groupée, MCP arrêté. Les sorties modifiées depuis la génération bloquent l’annulation afin de préserver les changements. Plusieurs écritures sur le même chemin nécessitent l’historique individuel. L’IA doit continuer à interroger le statut : le MCP n’est pas un agent autonome qui invente les étapes.

## OCR structuré

`extract_document_layout` complète `ocr_file` : blocs, titres estimés, champs usuels, tableaux alignés et confiance. `output_path` CSV/XLSX exporte les données détectées ; les valeurs restent du texte, sans formule déduite. L’analyse géométrique est heuristique : vérifier montants, cellules fusionnées, tableaux complexes et scans dégradés. Une page est traitée par appel, en français/anglais.

## Stockage et confidentialité

Les profils, modèles de composition, index, propositions et workflows sont conservés dans `%APPDATA%/org.mcpwin.desktop/.mcp-private`, hors accès MCP. Ils contiennent des extraits documentaires et ne sont pas chiffrés au repos. Les sauvegardes restent dans `.mcp-history` des dossiers partagés, également exclu des outils distants. Le journal d’activité visible reste limité à 100 opérations en mémoire.

Le cache d’extraction est borné à 128 Mio ; les propositions à 512 Mio et les workflows à 128 Mio. Les anciens éléments ne sont pas effacés automatiquement lorsqu’ils pourraient servir à une restauration ; un quota plein est signalé. Les limites générales de 25 Mio par document et les permissions v0.4 s’appliquent toujours.

La connexion extérieure conserve HTTPS, tunnel chiffré et jeton Bearer obligatoire. Le relais Cloudflare peut accéder au trafic qu’il termine ; il ne s’agit pas de chiffrement de bout en bout jusqu’à l’assistant.
